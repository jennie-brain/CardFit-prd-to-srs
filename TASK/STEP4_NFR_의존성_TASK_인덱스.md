# Step 4 NFR·의존성 TASK 인덱스

## 개요

REQ-NF 9건을 성능·신뢰성·가용성·보안·최신성·비용/관측성의 실행 TASK로 변환한다. 각 NFR은 측정 대상, 임계치, 검증 코드, 실패 조치와 선행 기능을 명시한다.

## NFR 목록

| TASK | 요구사항 | 임계치·핵심 결과 | 주요 선행 |
|---|---|---|---|
| NFR-001 계산·근거 성능 | NF-001·002 | 계산 p95≤5초, 근거 거부 p95≤500ms | COMMAND-003, QUERY-002, TEST-002·003 |
| NFR-002 계산 신뢰성·Rule 회귀 | NF-003 | 오류율≤0.1%, 불일치 0, ≥200건 | COMMAND-003·007, TEST-002 |
| NFR-003 가용성·Health·배포 | NF-004 | M1 smoke, M2≥99.5% | API-005, QUERY-004, TEST-006 |
| NFR-004 오조회·감사·보존 | NF-005·008 | 오조회 0, 최소 로그·마스킹 | 모든 데이터 경계, TEST-005 |
| NFR-005 Rule 최신성 | NF-006 | 7일 경고, 30일 제외 | COMMAND-007, QUERY-004 |
| NFR-006 비용·Guardrail 관측 | NF-007·009 | M1 $2, M2 $50, 80/100% 조치 | API-005, QUERY-004, TEST-006·007 |

## 의존성 표기 규칙

- `Depends on`에는 실제 착수 또는 완료를 막는 선행 TASK만 둔다.
- `Blocks`에는 이 TASK의 산출물 없이는 완료 판정을 내릴 수 없는 후행 TASK를 둔다.
- 정책 승인·실제 내부 계약은 TASK 번호 대신 명명된 External Blocker로 표시한다.
- M2 NFR은 M1 합격을 차단하지 않으며 같은 문서 안에서도 단계별 DoD를 분리한다.

## 결론

NFR은 기능 개발 뒤의 부가 점검이 아니라 기능 DoD의 필수 증거다. 전체 연결은 `STEP4_전체_TASK_의존성_매트릭스.md`에서 관리한다.
