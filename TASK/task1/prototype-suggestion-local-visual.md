# CardFit 로컬 시각 프로토타입 축약안

> **상태: 축약 실행 참고본(2026-08-27).** 현재 계획 정본은 [`prototype-suggestion.md`](prototype-suggestion.md)의 19건이며, 최초 시각 실행은 그 문서의 `P-VIS-01~03` 경량 체크포인트를 따른다. 이 문서는 확정된 시각 프로토타입 정책을 짧게 모아보는 용도이며, 11건을 독립 정본으로 취급하지 않는다.

## 목적

[`prototype-suggestion.md`](prototype-suggestion.md)의 19건 본 개발 연결형 슬라이스에서, **로컬에서 빠르게 화면의 설득력과 사용 흐름만 확인하는 범위**를 한 차례 더 추린 문서다.

이 문서의 목표는 다음 질문에 답하는 것이다.

> 혼인을 앞둔 사용자가 미래지출을 입력하고, 세 시나리오의 유지·변경 결과와 근거를 이해할 수 있는가?

백엔드 연동, 실제 금융 데이터, API 계약 검증, 계산 정확도, 배포 품질을 검증하는 계획이 아니다. 본 개발으로 이어지는 정본 계획은 원문 `prototype-suggestion.md`와 54개 TASK 문서다.

### 로컬 대체 방식

- 화면 데이터는 별도 서버 없이 `features/cardfit-prototype/fixtures/`의 **비식별 TypeScript Fixture**로 제공한다.
- 화면 타입은 `features/cardfit-prototype/lib/view-model.ts`를 단일 진입점으로 사용하고 컴포넌트 안에 임의 타입을 만들지 않는다.
- 입력 제출은 실제 저장·계산이 아니라 미리 준비한 결과 상태를 전환한다.
- 상태별 직접 진입은 허용된 `state` query로 재현하며 일반 사용자에게 상태 선택기를 노출하지 않는다.
- 금액·카드명·혜택은 예시임을 표시하고, 실제 추천·절감액·정확도처럼 보이는 주장은 넣지 않는다.
- 최초 체크포인트는 `/plan`과 `/result` 두 라우트만 사용한다.

### 2단계 — 입력까지의 첫 완주

### 3단계 — 결과와 판단의 핵심 장면

`UX-003 → UI-004 → UI-005`

- 차액·조건·기준일을 예시 데이터로 표시

### 4단계 — 근거와 다음 행동

- 근거 펼침/접힘과 불완전 데이터 안내
- 조합 선택 확인
- 카드사 공식 화면으로 이동한다는 경계 고지

## 구현 제약

이번 축약안에서는 아래를 하지 않는다.

- DB, MyData Adapter, Server Action, HTTP API 구현
- 실제 카드 혜택 계산·추천·순위 산출
- `DATA-*`, `API-*`, `SPEC-*` 계약 확정
- `COMMAND-*`, `QUERY-*` 로직 연결
- Gemini 등 AI 설명 생성
- 로그인·동의·카드 신청·해지 실행
- 성능·보안·배포·운영 모니터링 구축
- 자동 테스트 TASK를 완료 처리

정적 데이터는 화면 상태를 보여주기 위한 재료일 뿐이며, 정책 승인·계산 검증을 대체하지 않는다.

## 확정된 축약 UX 정책

### 문체와 상태

- 상태 제목과 일반 안내는 차분한 해요체를 사용한다.
- 계산 사실·적용 조건·스코프·주의사항은 합니다체를 사용한다.
- CTA는 `다시 시도하기`, `미래지출 입력하기` 같은 행동형 명사구로 쓴다.
- 혜택·정확성·발급 가능성을 보장하거나 사용자를 탓하는 표현은 사용하지 않는다.
- `partial`에서는 추천 결과를 숨기고 `stale`에서는 데이터 기준일을 표시한다.

### 미래지출 입력

- 입력 금액은 빈 값으로 시작한다. 사용자가 선택할 때만 수정 가능한 비개인화 예시를 적용한다.
- 출처·기준일·최신성·편향 검토 전에는 예시를 `업계 평균`이라고 표현하지 않는다.
- 미래지출은 여러 건을 추가·수정·삭제할 수 있다.
- 각 항목은 `한 번 쓰는 금액`(`ONE_TIME`) 또는 `매달 쓰는 금액`(`MONTHLY`)과 연·월 시점을 가진다.
- 카테고리는 `주거`, `가구·가전`, `예식`, `여행`, `교통`, `생활비`, `교육`, `의료`, `기타` 대분류에서 선택한다. `기타`에서만 직접 입력한다.
- 증가·감소를 따로 묻지 않는다. 비교 가능한 과거 월평균이 있을 때만 시스템이 방향과 차액을 표시한다.
- 금액은 만원 단위로 고정 입력하고 전체 원 금액과 필요 시 억 단위 읽기 표현을 병기한다.
- `원·만 원·억 원` 전환 탭과 소수 입력은 사용하지 않는다. 빠른 금액 추가·실행 취소·지우기를 제공한다.
- 일시불·할부 선택과 할부 개월은 입력받지 않는다. 할부 수수료·월별 실적 반영·무이자 조건은 결과의 미반영 항목에 표시한다.
- 최대 입력 금액과 상한 초과 상태를 임의로 만들지 않는다. 빈 값·0원·음수·비숫자만 최초 체크포인트에서 검증한다.

### 세 시나리오와 판정

| 내부 값 | 화면 라벨 | 접근성 이름 |
|---|---|---|
| `LOW` | 더 적게 | 예상 지출보다 적게 쓸 때 |
| `BASE` | 예상한 만큼 | 예상한 만큼 쓸 때 |
| `HIGH` | 더 많이 | 예상 지출보다 많이 쓸 때 |

- `예상한 만큼`을 기본 선택한다.
- 현재 조합과 변경 조합의 계산 결과가 같으면 `유지`로 분류한다.
- 동률은 `현재 조합을 유지해도 예상 혜택 차이가 없습니다.`처럼 설명하고 유지가 더 유리하다고 주장하지 않는다.
- `유지`와 `변경`은 같은 위계의 정상 결과이며 변경을 성공 상태처럼 강조하지 않는다.
- 여러 변경 후보끼리의 동률 정렬은 미확정이므로 최초 체크포인트에서 후보 순위를 표시하지 않는다.

### 결과 요약과 근거

- 대표 숫자는 같은 기준기간의 `총 예상 혜택 - 연회비`인 **예상 순혜택**이다.
- 기본 결과에는 예상 순혜택, 총 예상 혜택, 연회비, 결과에 가장 크게 영향을 준 영역별 한도, 데이터 기준일을 표시한다.
- `혜택 한도 월 1만 원` 대신 `생활 할인 월 최대 1만 원`처럼 적용 영역과 기간을 함께 쓴다.
- `계산 근거 보기`에는 영역별 계산식, 한도 적용 전·후 금액, 순혜택 계산, 전월 실적 등 조건, 제외·미반영 항목, 기준일·규칙 버전을 제공한다.
- 결과 해석에 중요한 미반영 항목은 근거가 접힌 상태에서도 짧게 고지한다.
- 최초 체크포인트에는 AI 설명과 비활성 placeholder를 모두 만들지 않는다.

### 고지 경계

- CardFit은 카드 신청·발급·해지를 대신하지 않는다.
- 조합 저장과 실제 카드 행동 완료를 서로 다른 상태로 표현한다.
- 외부 이동 직전에는 연회비·전월 실적·발급 조건을 카드사에서 다시 확인하도록 안내한다.
- `COMMAND-008` 승인 전 고지 문구는 PRD 기반 후보이며 본 개발에서 승인 문구로 교체한다.

## 최소 화면 목록

최초 `P-VIS-01~03`은 다음 두 라우트에서 확인한다.

1. `/plan`: 미래지출 입력 → 카드 조건 확인
2. `/result`: 세 시나리오 → 유지·변경 결론 → 예상 순혜택 → 계산 근거

후속 체크포인트에서 온보딩, 플랫폼 상태, 계산·데이터 품질 상태 전체, 조합 선택, 외부 이동을 추가한다.

## 프로토타입 완료 기준

- [ ] 로컬 실행 명령 한 번으로 화면을 열 수 있다.
- [ ] `/plan`에서 미래지출을 한 건 이상 입력하고 카드 조건 단계로 이동할 수 있다.
- [ ] `더 적게`·`예상한 만큼`·`더 많이`를 전환하면 선택 상태와 결과 설명이 바뀐다.
- [ ] 유지·변경 결론, 예상 순혜택, 총 예상 혜택, 연회비, 영역별 핵심 한도를 확인할 수 있다.
- [ ] 계산식·한도 적용 전후·조건·제외 항목·기준일·규칙 버전을 disclosure에서 확인할 수 있다.
- [ ] 할부 관련 미반영 경계와 Fixture 예시 고지가 보인다.
- [ ] 모바일 폭에서 가로 스크롤 없이 핵심 CTA를 사용할 수 있다.
- [ ] 검증되지 않은 사용자 수·로고·절감액·추천 보장 문구가 없다.
- [ ] 계획 정본 19건 중 어떤 TASK도 `Done`으로 닫지 않고 시각 검토 체크포인트만 기록한다.

## 아직 확정하지 않은 사항

- 라이트 모드 색상 후보는 `reports/CardFit_Lightmode_Color_Palette.html`에서만 검토하며 최종 token으로 확정하지 않았다.
- breakpoint, 화면 최대 폭, 플랫폼·카드사 브랜드 표기 방식은 미확정이다.
- 시각 검토 판정 기록과 접근성 리뷰 증거 방식은 미확정이다.
- 여러 변경 후보끼리 동률일 때의 정렬·대표 후보 선택 규칙은 미확정이다.
- 할부의 월별 실적·혜택 귀속 정책과 실제 제품 입력 상한은 미확정이다.
