# CardFit 로컬 시각 프로토타입 축약안

> **상태: 참고용·대체됨(2026-08-27).** 현재 계획 정본은 [`prototype-suggestion.md`](prototype-suggestion.md)의 19건이며, 최초 시각 실행은 그 문서의 `P-VIS-01~03` 경량 체크포인트를 따른다. 이 문서의 11건 독립 정본화 결정은 더 이상 현재 실행 기준이 아니다.

## 목적

[`prototype-suggestion.md`](prototype-suggestion.md)의 19건 본 개발 연결형 슬라이스에서, **로컬에서 빠르게 화면의 설득력과 사용 흐름만 확인하는 범위**를 한 차례 더 추린 문서다.

이 문서의 목표는 다음 질문에 답하는 것이다.

> 혼인을 앞둔 사용자가 미래지출을 입력하고, 세 시나리오 결과와 근거를 이해한 뒤, 다음 행동을 선택하는 화면 흐름이 직관적인가?

백엔드 연동, 실제 금융 데이터, API 계약 검증, 계산 정확도, 배포 품질을 검증하는 계획이 아니다. 본 개발으로 이어지는 정본 계획은 원문 `prototype-suggestion.md`와 54개 TASK 문서다.

## 범위 판정

### 포함: 시각·상호작용 확인용 11건

| 구분 | TASK | 이번 프로토타입에서 확인할 것 |
|---|---|---|
| UX | `UX-001` | 정보구조, 상태 언어, 공통 접근성 원칙 |
| UX | `UX-002` | 온보딩 → 미래지출 입력 흐름 |
| UX | `UX-003` | 계산 진행 → LOW/BASE/HIGH 결과 흐름 |
| UX | `UX-004` | 근거 확인 → 조합 선택 → 외부 이동 경계 |
| UI | `UI-001` | 색상·타이포·간격·컴포넌트 기반 |
| UI | `UI-002` | 온보딩·플랫폼 상태·스코프 고지 화면 |
| UI | `UI-003` | 미래지출·카드 제약 입력 화면 |
| UI | `UI-004` | 계산 중·부분 데이터·오래된 데이터·실패 상태 화면 |
| UI | `UI-005` | 세 시나리오와 유지/변경 결과 화면 |
| UI | `UI-006` | 배분·근거 펼침 화면. AI 설명은 제외 |
| UI | `UI-007` | 조합 선택과 카드사 외부 이동 안내 화면 |

### 로컬 대체 방식

- 화면 데이터는 별도 서버 없이 `fixtures` 또는 컴포넌트 내부의 **비식별 정적 JSON**으로 제공한다.
- 입력 제출은 실제 저장·계산이 아니라 미리 준비한 결과 상태를 전환한다.
- LOW/BASE/HIGH 탭, 정상·부분·오래됨·실패 상태는 화면 전환으로 확인한다.
- 금액·카드명·혜택은 예시임을 표시하고, 실제 추천·절감액·정확도처럼 보이는 주장은 넣지 않는다.
- 현재 서비스 라우트가 없으면 CTA는 로컬 결과 화면 또는 `#service-entry` 앵커로 연결한다.

## 추천 실행 순서

### 1단계 — 시각 언어와 공통 골격

`UX-001 → UI-001`

- 모바일 우선 그리드와 화면 폭
- 헤딩·본문·보조 문구의 위계
- 기본/보조/경고/오류 상태 색상
- 버튼, 카드, 배지, 탭, 아코디언의 기본 스타일
- 키보드 포커스와 명도 대비

### 2단계 — 입력까지의 첫 완주

`UX-002 → UI-002 → UI-003`

- “결혼 후 달라질 지출”이라는 맥락을 설명
- 마이데이터 연결 상태를 실제 연동 없이 시각화
- 주거·예식·여행·생활비 등 미래지출 입력
- 입력 완료 후 계산 시작 CTA

### 3단계 — 결과와 판단의 핵심 장면

`UX-003 → UI-004 → UI-005`

- 계산 중 상태와 완료 상태
- LOW/BASE/HIGH 시나리오 탭
- 유지/변경 결론의 시각적 위계
- 차액·조건·기준일을 예시 데이터로 표시

### 4단계 — 근거와 다음 행동

`UX-004 → UI-006 → UI-007`

- 성과 구간·한도·연회비·제외조건·기준일·규칙 버전의 근거 카드
- 근거 펼침/접힘과 불완전 데이터 안내
- 조합 선택 확인
- 카드사 공식 화면으로 이동한다는 경계 고지

## 구현 제약

이번 축약안에서는 아래를 하지 않는다.

- DB, MyData Adapter, Server Action, HTTP API 구현
- 실제 카드 혜택 계산·추천·순위 산출
- `DATA-*`, `API-*`, `SPEC-*` 계약 확정
- `COMMAND-*`, `QUERY-*` 로직 연결
- Gemini 등 AI 설명 생성
- 로그인·동의·카드 신청·해지 실행
- 성능·보안·배포·운영 모니터링 구축
- 자동 테스트 TASK를 완료 처리

정적 데이터는 화면 상태를 보여주기 위한 재료일 뿐이며, 정책 승인·계산 검증을 대체하지 않는다.

## 최소 화면 목록

1. 시작/스코프 고지
2. 플랫폼 상태 확인
3. 미래지출 입력
4. 계산 진행
5. 데이터 품질 상태(정상·부분·오래됨·실패)
6. 시나리오 결과(LOW/BASE/HIGH)
7. 배분·근거 상세
8. 조합 선택 및 외부 이동 안내

## 프로토타입 완료 기준

- [ ] 로컬 실행 명령 한 번으로 화면을 열 수 있다.
- [ ] 입력 → 계산 중 → 결과 → 근거 → 선택 흐름을 새로고침 없이 완주할 수 있다.
- [ ] 정상·부분·오래됨·실패 상태가 서로 다른 문구와 시각 상태로 구분된다.
- [ ] LOW/BASE/HIGH를 전환하면 선택 상태와 결과 설명이 바뀐다.
- [ ] 근거 6개 항목과 데이터 기준일을 확인할 수 있다.
- [ ] 신청·해지를 대신 실행하지 않는다는 고지가 보인다.
- [ ] 모바일 폭에서 가로 스크롤 없이 핵심 CTA를 사용할 수 있다.
- [ ] 검증되지 않은 사용자 수·로고·절감액·추천 보장 문구가 없다.
- [ ] 본 프로토타입에 포함된 11개 TASK는 `Done`으로 닫지 않고 시각 검토 체크포인트만 기록한다.

## 원안과의 차이

| 항목 | 본 문서: 로컬 시각안 | 원문: 본 개발 연결형 |
|---|---|---|
| 목적 | 화면 구조·카피·상태 전환 검증 | 계약부터 본 개발로 이어지는 UI/UX 슬라이스 |
| 범위 | UX 4 + UI 7 = 11건 | 계약 8 + UX 4 + UI 7 = 19건 |
| 데이터 | 로컬 정적 Fixture | `MOCK-001`과 승인된 ViewModel 계약 |
| 계산 | 준비된 예시 상태 전환 | 실제 로직으로 교체 가능한 계약 기반 연결 |
| 품질 판정 | 사람의 시각 검토 | 테스트·NFR·계약 검증까지 포함 |
| 결과 | 빠른 방향성 확인 | 본 개발에 이어지는 체크포인트 |

## 다음 단계로 넘길 때

시각 방향이 승인되면 원문 계획의 `DATA-* → API-* → SPEC-001 → MOCK-001` 순서로 계약을 확정하고, 이 문서의 정적 Fixture를 계약에 맞춰 교체한다. 그때부터 각 UI TASK의 테스트·NFR Gate를 적용하며, 이 축약안의 화면 확인을 TASK `Done`으로 소급하지 않는다.
