# GitHub Project 용 TASK — UX-005 조합 선택·외부 이동 경계 설계

## Summary
- 목적: 제품 내 조합 선택과 실제 카드 발급·해지 행동을 구분해 사용자가 실행 대행으로 오인하지 않게 한다.
- REQ: REQ-FUNC-009·010, ADR-002

## References (Spec & Context)
- 계약: DATA-004, API-002·006
- 로직: COMMAND-004·008
- 후행 구현: UI-007

## Scope
- 선택 확인·완료·만료·중복 상태, 외부 이동 사전 고지와 CTA 계층
- 카드 신청·해지 프로세스 설계는 범위 밖

## Task Breakdown
- [ ] 선택 전 확인 정보와 완료 피드백을 설계한다.
- [ ] 만료 후보·소유권 오류·중복 요청의 복구 흐름을 정한다.
- [ ] 외부 카드사 이동과 CardFit 내부 선택을 시각·문구로 분리한다.
- [ ] 유지 결론 사용자의 다음 행동과 선택률 제외 의미를 정의한다.

## Acceptance Criteria (BDD/GWT)
### Scenario 1: 정상 선택
- Given: 유효 변경 후보다.
- When: 저장·확정한다.
- Then: 무엇을 선택했는지와 CardFit이 실행하지 않는 범위를 이해한다.
### Scenario 2: 만료 후보
- Given: 후보가 만료됐다.
- When: 선택한다.
- Then: 실행되지 않았음을 알고 재계산으로 이동한다.
### Scenario 3: 외부 이동
- Given: 카드사 링크를 선택한다.
- When: 이동 전 고지를 본다.
- Then: 신청 조건 재확인과 대행 미제공을 이해한다.

## Technical & Non-Functional Constraints
- 승인된 카드사 도메인과 DATA-004 문구를 사용한다.
- 신규카드 발급을 과도하게 유도하지 않는다.

## Definition of Done
- [ ] 선택·만료·외부 이동 wireflow와 카피가 승인됐다.
- [ ] UI-007과 TEST-005·006에 추적된다.
- [ ] 북극성 선택률 산식과 모순이 없다.

## Dependencies & Interactions
- Depends on: UX-001·003·004, DATA-004, COMMAND-004
- Blocks: UI-007, UX-006
- 변경 전파: 선택 UI·Outcome 기준선·Analytics·E2E

## Open Decisions
