## Task Breakdown
- [ ] Tailwind theme token과 shadcn/ui 기본 컴포넌트를 구성한다.
- [ ] Loading/Empty/Partial/Stale/Error/Unavailable 상태 컴포넌트를 만든다.
- [ ] 공통 form field와 서버 오류 매핑 패턴을 만든다.

- [ ] 허용되지 않은 arbitrary value·inline style 검사를 정의한다.

## Acceptance Criteria (BDD/GWT)
### Scenario 1: 키보드 조작
- Given: 핵심 흐름의 상호작용 요소다.
- When: 키보드만 사용한다.
- Then: 논리적 순서로 접근·실행 가능하고 focus가 보인다.
### Scenario 2: 입력 오류
- Given: 서버 field error가 있다.
- When: 폼이 다시 표시된다.
- Then: 오류가 해당 label/input과 연결되고 screen reader가 인식한다.
### Scenario 3: 스타일 일관성
- Given: Production UI를 검사한다.
- When: lint를 실행한다.
- Then: 비허용 inline style·arbitrary value는 0건이다.

## Technical & Non-Functional Constraints
- WCAG 2.2 AA critical 오류 0건을 목표로 한다.
- Client Component 범위를 상호작용에 필요한 최소 수준으로 제한한다.
