# GitHub Project 용 TASK — UI-003 미래지출·제약 입력

## Summary
- 목적: 사용자가 미래지출을 한 번 입력하고 카드 수·연회비·신규발급 제약을 부담 없이 설정하게 한다.
- REQ: REQ-FUNC-001A/B·003A/B·008, UX-V-001
- 구현 책임: UX-002의 입력 구조와 오류 피드백을 form·Server Action 연결로 구현한다.

## References (Spec & Context)
- 로직: COMMAND-001, QUERY-001
- 계약: DATA-001, API-002
- 테스트: TEST-001·006

## Scope
- SINGLE/RANGE, 카테고리·금액·시점, 자유 입력·양방향, 제약 폼
- M2 개인 초기값과 이력 부족 fallback
- 입력 흐름 재설계와 이벤트 종류 필수 선택 UI는 범위 밖

## Task Breakdown
- [ ] 서버와 공유하는 schema로 form을 구성한다.
- [ ] 단일·범위 모드와 최소≤예상≤최대 안내를 제공한다.
- [ ] 자유 카테고리와 증가·감소를 별도 이벤트 선택 없이 입력한다.
- [ ] field error를 값 보존 상태로 표시하고 첫 오류에 focus한다.
- [ ] M1에서는 빈 입력·비개인화 예시를 표시하고, M2에서만 개인화 여부·기준기간 표시를 추가한다.

## Acceptance Criteria (BDD/GWT)
### Scenario 1: 한 번 입력
- Given: 예상금액을 SINGLE로 입력한다.
- When: 저장한다.
- Then: 추가 금액 입력 없이 세 시나리오 생성 준비가 완료된다.
### Scenario 2: 범위 오류
- Given: 최소>예상 또는 예상>최대다.
- When: 제출한다.
- Then: 저장·계산 없이 인라인 오류와 수정 위치를 표시한다.
### Scenario 3: 이력 부족
- Given: 과거 이력이 3개월 미만이다.
- When: 화면을 연다.
- Then: 임의 업계 평균 대신 빈 폼·비개인화 예시를 표시한다.

## Technical & Non-Functional Constraints
