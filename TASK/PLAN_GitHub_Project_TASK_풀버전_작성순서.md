# GitHub Project TASK 풀버전 작성 계획

## Summary

이 계획은 `SRS-Drafts/SRS_CardFit_v1.6_GPT-5.6-SOL.md`를 기준으로 GitHub Project용 풀버전 TASK 본문을 한 단계씩 작성하기 위한 순서와 상호작용을 정의한다. 현재 단계에서는 TASK 본문을 생성하거나 제품 코드를 구현하지 않는다. 사용자가 각 단계의 TASK 작성을 후속 프롬프트로 명시적으로 요청할 때에만 해당 문서를 작성한다.

## 작성 원칙

1. TASK 한 개는 하나의 검증 가능한 책임만 가진다.
2. 선행 정책이나 계약이 확정되지 않은 TASK는 구현 가능한 것처럼 작성하지 않고 `Blocked`로 표시한다.
3. 각 TASK는 `Summary`, `Description`, `Acceptance Criteria (GWT)`, `Non-Functional Constraints`, `Labels`를 반드시 포함한다.
4. 풀버전에서는 템플릿 필수 항목에 범위·제외 범위·의존성·상호작용·산출물·Definition of Done·위험을 추가한다.
5. 실제 SRS의 REQ ID, Sequence Diagram, ERD 엔터티를 연결한다.
6. M1 핵심 가치 경로가 완성되기 전에는 M2 자동화·AI·실제 통합 TASK를 앞당기지 않는다.
7. Mock 성공과 실제 뱅크샐러드 통합 성공을 분리한다.
8. 각 TASK는 사용자의 승인 후 다음 TASK 작성으로 이동한다.

## 후속 프롬프트 사용 방법

사용자는 다음과 같이 한 단계씩 요청한다.

> `TASK 풀버전 작성 계획의 1번 정책 기준선 TASK를 템플릿에 맞춰 풀버전으로 작성해줘. 아직 다음 TASK는 작성하지 마.`

각 응답에서는 요청한 순서의 TASK 한 개 또는 명시된 TASK 묶음만 작성한다. 사용자가 해당 문서를 검토하고 승인하기 전에는 다음 순서의 문서나 구현 작업을 진행하지 않는다.
