# GitHub Project 용 TASK — UX-001 공통 정보구조·상태 언어·접근성

## Summary
- 목적: CardFit 전 화면의 정보 우선순위, 상태 명칭, 행동 문구와 접근성 원칙을 설계한다.
- REQ: REQ-UI-001~005, UX-V-001~008

## References (Spec & Context)
- SRS: 3.1, 9.5, C-TEC-004
- 후행 구현: UI-001~009

## Scope
- 내비게이션·페이지 계층, 상태 용어, CTA 원칙, focus·키보드·오류 전달 기준
- Tailwind class·React 컴포넌트 코딩은 범위 밖

## Task Breakdown
- [ ] M1/M2 사용자 여정과 화면 계층을 정의한다.
- [ ] loading·empty·partial·stale·error·unavailable·success의 의미를 정의한다.
- [ ] 유지·변경·판정 불가·미측정 용어와 금지 표현을 정한다.
- [ ] 키보드·screen reader·색상 비의존 표현의 설계 원칙을 정한다.

## Acceptance Criteria (BDD/GWT)
### Scenario 1: 상태 구분
- Given: 데이터 없음·조회 실패·판정 불가 상태다.
- When: UX 명세를 검토한다.
- Then: 세 상태의 문구·행동·시각 신호가 서로 구분된다.
### Scenario 2: 접근성
- Given: 핵심 여정을 키보드·screen reader로 사용한다.
- When: 설계 산출물을 검토한다.
- Then: focus 순서·label·오류 전달 기준이 누락 없이 정의된다.
