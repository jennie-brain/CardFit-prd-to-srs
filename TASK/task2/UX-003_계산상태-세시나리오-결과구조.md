# GitHub Project 용 TASK — UX-003 계산 상태·세 시나리오 결과 구조

## Summary
- 목적: 계산 진행·오류·데이터 품질과 LOW·BASE·HIGH의 유지/변경 결론을 이해 가능한 정보 구조로 설계한다.
- REQ: REQ-FUNC-004·005·011, UX-V-002·003·005

## References (Spec & Context)
- 계약: API-003·006
- 로직: COMMAND-003, QUERY-002
- 후행 구현: UI-004·005

## Scope
- loading·timeout·partial·stale 구조, BASE 기본 노출, 탭·차액·조건부 결론
- 계산식과 결과 정렬 구현은 범위 밖

## Task Breakdown
- [ ] 계산 상태별 메시지·복구 행동을 설계한다.
- [ ] BASE 우선, LOW/HIGH 탐색 구조를 설계한다.
- [ ] 유지 결론을 실패가 아닌 정상 결과로 표현한다.
- [ ] 금액·기준기간·차액·데이터 기준일의 정보 계층을 정한다.

## Acceptance Criteria (BDD/GWT)
### Scenario 1: 시나리오 탐색
- Given: 세 결과가 준비됐다.
- When: 결과에 진입·탭 전환한다.
- Then: BASE를 먼저 이해하고 추가 계산 없이 LOW/HIGH 차이를 비교한다.
### Scenario 2: 유지 결과
- Given: 임계 미달이다.
- When: 결과를 본다.
- Then: 변경 실패가 아니라 유지가 유리한 이유로 이해한다.
### Scenario 3: 오래된 캐시
- Given: 최근 확인 데이터로 계산했다.
- When: 결과를 본다.
- Then: 경고·기준일·결론의 사용 조건을 함께 이해한다.

## Technical & Non-Functional Constraints
- 색상만으로 시나리오·경고를 구분하지 않는다.
