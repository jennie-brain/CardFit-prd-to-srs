# Step 5 UI/UX TASK 인덱스

## 개요

Step 1~4에서 고정한 계약·로직·테스트·비기능 상태를 사용자가 이해하고 조작할 수 있는 화면으로 변환한다. UI는 서버 상태를 새로 정의하지 않으며, 정상·로딩·빈 상태·부분 데이터·오류·접근성 상태를 모두 명시한다.

## 공통 UI 상태 계약

- `loading`: 중복 제출을 막고 진행 중 작업과 취소/재시도 가능 여부를 표시한다.
- `empty`: 실제 데이터 없음과 조회 실패를 구분한다.
- `partial/stale`: 경고, 기준일, 계산 가능 여부를 함께 표시한다.
- `error`: 사용자 수정 가능 오류와 운영자 조치 오류를 구분하며 내부 stack을 노출하지 않는다.
- `unavailable`: AI·관측처럼 선택 기능이 불가능해도 핵심 결과는 유지한다.
- `success`: 다음 행동과 되돌리기·재계산 조건을 분명하게 제시한다.

## 완료 조건

- UX-V-001~008이 최소 한 개 UI TASK와 TEST에 연결된다.
- REQ-UI-001~005가 UI-001과 모든 화면 DoD에 반영된다.
- M1 핵심 수직 경로가 `입력→계산→결론→차액→근거→선택`으로 이어진다.
