# CardFit 랜딩페이지 최종 체크리스트

검토 대상: [`landing/index.html`](../landing/index.html)  
검토 기준: 사용자 제공 「랜딩페이지 고도화 전략」 및 「랜딩페이지 체크리스트」, CardFit PRD v1.3·SRS v1.6의 확정 범위

## 결론

**조건부 통과(Conditional Pass)** 입니다. 혼인을 앞둔 마이데이터 사용자의 불안을 줄이면서 미래지출을 빠르게 입력·비교하게 만드는 랜딩페이지 구조는 구현되었습니다. 다만 현재 저장소에 서비스 본문 라우트가 없으므로 CTA 연결과 실제 운영 증거(검증된 수치·로고·추천사)는 출시 전 보완이 필요합니다.

## STEP 0. 서비스 유형 진단

- [x] **A 유형 — 확신 제공형·불안 해소형 (주 유형)**
- [ ] B 유형 — 기술 몰입형
- [ ] C 유형 — 결과 지향형 (보조 전략으로 일부 적용)

혼인·이사로 지출이 바뀌는 사용자는 “카드를 바꿨다가 손해 보면 안 된다”는 불안을 갖습니다. 따라서 핵심 메시지는 속도보다 **근거, 기준일, 데이터 상태, 판단 경계**입니다. 동시에 “미래지출 1회 입력 → 세 시나리오 비교”라는 C 유형의 단순한 결과 전달을 보조적으로 사용했습니다.

## STEP 1. 공통 핵심 코어 점검

| 항목 | 판정 | 확인 내용 |
|---|---|---|
| 명확한 헤드라인 | [x] | “결혼 후 카드, 감으로 바꾸지 마세요.”라는 문제·불안을 3초 안에 전달 |
| 보조 설명 | [x] | 미래지출 입력, 세 시나리오, 근거 공개 방법을 설명 |
| 직관적 이미지/미디어 | [x] | 실제 수치를 주장하지 않는 CSS 기반 결과 화면 목업 제공 |
| 동사형 CTA | [x] | “내 지출로 계산해보기”, “현재 서비스에서 계산 시작” |
| CTA 반복 배치 | [x] | 히어로·워크플로우 중단·하단 CTA를 제공 |
| 숫자/로고 증명 | [△] | 검증된 사용자 수·파트너 로고가 없어 허위 증거를 만들지 않고, 결정론적 계산·근거 공개·AI 역할 분리라는 제품 원칙을 신뢰 증거로 사용 |

## STEP 2. 유형별 전략 요소 점검

### A 유형 — 확신 제공형·불안 해소형

| 항목 | 판정 | 확인 내용 |
|---|---|---|
| 워크플로우 | [x] | 미래지출 입력 → LOW/BASE/HIGH 비교 → 근거와 함께 선택의 3단계 흐름 |
| 안전 장치 | [x] | 근거 6개 이상, 기준일·rule_version, 불완전 데이터 경고, AI 역할 분리, 신청·해지 경계 |
| 권위자 추천 | [ ] | 승인된 교수·전문가 추천사가 없음. 동의·출처·검증이 확보되기 전에는 삽입하지 않음 |

### C 유형 — 결과 지향형 (보조 적용)

| 항목 | 판정 | 확인 내용 |
|---|---|---|
| Input–Output | [x] | 미래지출 입력 → 세 시나리오 판단 화면으로 단순화 |
| 결과 갤러리 | [x] | 결과 카드와 시나리오 탭을 제공. 실제 카드 데이터가 아닌 구조 목업임을 명시 |
| Before & After/ROI | [ ] | 절감액·시간 수치는 검증된 기준선이 없어 보류. PRD의 운영 가정 수치를 마케팅 증거로 사용하지 않음 |

## STEP 3. 최종 자가 피드백

**고객의 첫 번째 생각(목표):** “결혼 후 지출을 반영해서 카드 선택을 근거와 함께 확인할 수 있겠군. 내 지출로 한번 계산해보고 싶다.”

**우리 페이지의 한 방:**

- [x] 압도적인 권위(A) 대신, 근거와 판단 경계를 투명하게 공개하는 신뢰 설계
- [ ] 놀라운 시연 영상(B)
- [△] 확실한 효율성 수치(C) — 검증된 기준선 확보 후 추가

## 출시 전 보완 항목

1. 현재 서비스 화면의 실제 경로가 확정되면 `landing/index.html`의 `data-service-cta` 링크를 해당 경로로 교체합니다.
2. 실제 결과 화면이 구현되면 CSS 목업을 승인된 캡처 또는 동작 데모로 교체합니다.
3. 사용자 수·평점·파트너 로고·추천사는 출처와 사용 승인을 확보한 뒤 추가합니다.
4. E0 기준선이 확정되면 ROI/Before & After 수치를 별도 검증 후 추가합니다.
5. 출시 전 실제 데이터 동기화 실패, 기준일 표시, 모바일 키보드·스크린리더 동작을 테스트합니다.

## 검토 메모

- “정확도 보장”, “절감 보장”, “표절률 0%”와 같은 과장 문구는 CardFit의 확정 범위와 맞지 않아 사용하지 않았습니다.
- 카드 신청·해지 실행을 대행한다고 오해할 수 있는 문구를 배제했습니다.
- 랜딩페이지는 현재 서비스 앞단의 Hook 역할이며, 본문 서비스의 기능·계산 정책을 새로 정의하지 않습니다.
