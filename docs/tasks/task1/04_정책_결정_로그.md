## 운영 규칙

- 정책이 확정되면 해당 TASK의 Open Decisions와 Decision Log를 함께 갱신한다.
- 정책 미확정 상태에서는 임시값을 제품 동작이나 테스트 expected 값으로 고정하지 않는다.
- 정책 변경 시 영향받는 Contract·Logic·Test·NFR TASK를 재검토한다.

## Decision Log

### 2026-08-26 — 확정 기준선 반영

- 개발 TASK 기준선은 54개로 확정했다.
- 정책 결정은 개발 TASK 수에 포함하지 않고 연결 TASK의 착수·완료 Gate로 관리한다.

### 2026-08-27 — DECISION-004 이력 부족 사용자의 초기값·예시 정책

- 결정: 미래지출 금액은 빈 값으로 시작하고, 사용자가 `예시 금액 적용하기`를 명시적으로 선택한 경우에만 수정 가능한 비개인화 예시를 입력한다.
- 표시: 예시 값은 개인 소비 데이터나 업계 통계를 기준으로 하지 않았음을 입력 영역 가까이에 표시한다.
- 금지: 승인된 출처·기준일·최신성·편향 검토 없이 `업계 평균`이라는 명칭이나 값을 사용하지 않는다.
- 승격: 업계 평균 분기는 위 검토가 승인된 뒤 M2 별도 변경 요청으로만 활성화한다.
- 근거: 빈 폼만 제공할 때의 입력 부담을 선택형 예시로 완화하면서, 출처 없는 수치를 통계·개인화 값으로 오인하는 위험을 차단한다.
- 영향: `docs/product/PRD_CardFit_v1.3.md` US-D AC4, `docs/technical/SRS_CardFit_v1.6_GPT-5.6-SOL.md` REQ-FUNC-008 AC3, `UX-002`, `UI-003`, `QUERY-001`.

### 2026-08-27 — DECISION-005 할부 귀속 정책 발견

- 상태: Open/Blocked.
- 발견: PRD·SRS는 `planned_at`이 속한 결제주기에 계획 지출을 귀속한다고만 정의하고, 할부 개월별 실적·혜택·수수료 반영 규칙은 정의하지 않는다.
- 금지: 승인 전 총액을 최초 결제월에 전부 귀속하거나 개월 수로 균등 분할하는 규칙을 제품 계산·Fixture의 실제 정책처럼 사용하지 않는다.
- 프로토타입 결정 필요: 할부 계획 입력을 시각화할지, 시각화한다면 계산 미반영 경계를 어떻게 고지할지 Grill T16에서 확정한다.
- 본 개발 Blocker: 할부 지원을 계산 범위에 포함하려면 카드사별 실적·혜택·무이자·수수료 규칙과 월별 반올림·잔액 귀속을 별도 승인해야 한다.
- 프로토타입 처리: 할부 옵션을 입력받지 않고 할부 지원을 암시하지 않는다. 결과 근거에 할부 관련 조건을 미반영 항목으로 표시하므로 로컬 시각 프로토타입 착수는 차단하지 않는다.

### 2026-08-27 — DECISION-006 미래지출 형태와 변화 방향 입력

- 결정: 사용자는 `한 번 쓰는 금액`과 `매달 쓰는 금액`을 선택하고 미래 금액과 연·월 시점을 입력한다. 증가·감소 방향은 별도로 선택하지 않는다.
- 도출: 비교 가능한 과거 월평균이 있으면 시스템이 미래 월 금액과의 방향·차액을 표시하고, 기준값이 없으면 방향을 임의 생성하지 않는다.
- 제외: 값과 사용자 효용이 미정인 `confidence`는 프로토타입에 노출하지 않는다.
- 경계: 월 반복 금액의 12개월 계산 귀속은 D6 승인 대상이며 이번 결정은 입력 UX와 비교 표시에 한정한다.
- 근거: 사용자가 이미 입력한 미래 금액과 보유 데이터를 다시 방향 선택으로 중복 입력하게 하지 않으면서, 일회성 총액과 반복 월 금액의 의미를 구분한다.

### 2026-08-27 — DECISION-007 미래지출 입력 상한 발견

- 상태: Open/Blocked.
- 결정 유예: 최대 입력 금액·카테고리별 상한·ONE_TIME/MONTHLY별 상한을 프로토타입에서 임의로 정하지 않는다.
- 프로토타입 검증: 빈 값·0원·음수·비숫자·RANGE 순서 오류만 처리하며 상한 초과 상태와 수치 안내는 제외한다.
- 승인 근거: 실제 대상 사용자의 금액 분포, 계산 성능, 데이터 타입과 오류 복구 UX를 확인한 뒤 본 개발 전에 확정한다.
- 영향: 실제 상한을 도입할 때 DATA-001·API-002·COMMAND-001·UX-002·UI-003·TEST-001을 같은 변경으로 갱신한다.
