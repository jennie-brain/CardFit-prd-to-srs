# CardFit 경량 시각 체크포인트 — 화면 워크스루

라운드: 2 · 기록 시각: 2026-08-27 15:33 실행 세션

이 문서는 브라우저를 볼 수 없는 검토자가 완료 기준 1~9를 판정할 수 있게, 실제로 렌더되는 텍스트와
상태 전이·뷰포트 처리·완주 경로를 적은 기록이다. 아래 `/plan`·`/result` 텍스트 전문은
`next dev` 기동 후 `curl`로 받은 응답에서 태그를 제거해 옮긴 것이다.

## 실행 증거 (완료 기준 1)

`npm run dev` 기동 로그의 해당 줄이다.

```
> cardfit-prototype@0.1.0 dev
> next dev
▲ Next.js 16.3.3 (Turbopack)
- Local:         http://localhost:3000
- Network:       http://192.168.35.101:3000
✓ Ready in 1976ms
```

로그가 출력한 실제 포트는 `3000`이므로 진입 URL은 **`http://localhost:3000/plan`** 이다.
같은 기동에서 받은 HTTP 상태는 다음과 같다.

```
DETECTED_PORT=3000
plan=200
result=200
result_state_unknown=200      (http://localhost:3000/result?state=partial)
root=404
```

루트 경로 `/`의 404는 범위 밖 라우트를 만들지 않은 결과다(spec §3.2, rules 006). 기준 1의 실패가 아니다.
`?state=partial`처럼 이번 체크포인트가 화면으로 만들지 않은 값이 와도 대표 Fixture가 그대로 렌더된다
(spec §5.2의 안전한 되돌림).

### 가능한 사용자 행동과 결과 이동 지점

| 행동 | 결과 |
| --- | --- |
| `예시 금액 적용하기` | 비개인화 예시 2건(생활비 MONTHLY 110만 원 / 예식 ONE_TIME 1,200만 원)이 목록에 추가되고, 버튼이 `예시 지우기`로 바뀌며 예시 고지 문구가 나타난다 |
| `예시 지우기` | 예시 항목만 목록에서 제거된다. 사용자가 직접 추가한 항목은 남는다 |
| 카테고리에서 `기타` 선택 | `카테고리 직접 입력` 필드가 같은 화면에 나타난다. 그 밖의 대분류에서는 나타나지 않는다 |
| 지출 형태 전환 | 금액 라벨이 `예상 지출 총액` ↔ `앞으로 예상하는 월 금액`, 시점 라벨이 `지출 예정 시기` ↔ `변경 시작 시기`로 바뀐다 |
| `+10만`·`+100만`·`+1,000만` | 현재 입력값에 더한다. 값이 비어 있으면 더한 금액만 남는다 |
| `실행 취소` | 직전 빠른 추가·금액 지우기 조작 이전 값으로 되돌린다. 이력이 없으면 비활성이다 |
| `금액 지우기` | 입력값을 비운다. 값이 비어 있으면 비활성이다 |
| `미래지출 추가하기` | 검증을 통과하면 목록에 한 건 추가되고 금액·직접 입력값이 초기화된다. 실패하면 화면 3의 오류 상태가 된다 |
| `수정하기`(항목별) | 그 항목이 입력 폼으로 불러와진다. 폼 제목이 `미래지출 수정`으로 바뀌고 금액 필드로 focus가 이동하며 해당 항목에 `수정 중` 배지가 붙는다 |
| `수정 내용 저장하기` | 같은 항목을 제자리에서 갱신한다. 항목 순서·`id`·과거 월평균·예시 표시는 보존되고 방향·차액이 새 금액으로 다시 계산된다 |
| `수정 취소하기` | 갱신하지 않고 편집 상태만 해제한다. 목록은 그대로다 |
| `미래지출 입력하기`(빈 상태) | 금액 입력 필드로 focus를 옮긴다 |
| `카드 조건 확인하기` | 목록이 1건 이상이면 주소 이동 없이 2단계로 전환한다. 0건이면 화면 3의 단계 이동 오류가 표시된다 |
| `삭제하기`(항목별) | 해당 항목을 목록에서 제거한다 |

### 미래지출 항목 한 건의 표시

`예시 금액 적용하기`를 누른 뒤 목록에 나타나는 두 항목의 렌더 내용이다.
과거 월평균이 있는 항목에만 방향·차액이 나타난다(spec §8.9, PRD US-F AC2).
각 항목에는 `수정하기`·`삭제하기` 버튼이 있어 spec §8.9의 추가·수정·삭제가 모두 가능하다.
수정 중인 항목은 `수정 중` 배지가 붙고 그 항목의 `수정하기` 버튼이 비활성되어, 색상 외의 신호로도
어떤 항목을 고치는 중인지 알 수 있다.

```
생활비                                  [예시 금액]
지출 형태      매달 쓰는 금액
최근 월평균    80만 원 (예시 데이터)
앞으로 예상하는 월 금액   110만 원 · 1,100,000원
변경 시작 시기  2026년 10월
예상 변화      월 30만 원 증가

예식                                    [예시 금액]
지출 형태      한 번 쓰는 금액
예상 지출 총액  1,200만 원 · 12,000,000원
지출 예정 시기  2026년 11월
예상 변화      비교할 과거 지출이 없어요
```

## 화면 3 — `/plan` 입력 오류

- **접근 URL**: `http://localhost:3000/plan` (같은 라우트의 오류 상태)
- **충족 완료 기준**: 2, 7, 8

프로토타입 검증 대상은 빈 값·0원·음수·비숫자뿐이다. 상한 초과 오류와 상한 안내 문구는
`DECISION-007` 승인 전까지 만들지 않는다(spec §8.10).

| 입력 | 렌더되는 오류 문구 | 부가 동작 |
| --- | --- | --- |
| 금액 빈 값 → `미래지출 추가하기` | `입력 오류: 금액을 입력해 주세요.` | 금액 필드로 focus 이동, `aria-invalid` 설정 |
| 금액 `0` | `입력 오류: 0원보다 큰 금액을 입력해 주세요.` | 같음 |
| 금액 `-100` | `입력 오류: 0원보다 큰 금액을 입력해 주세요.` | 같음 |
| 금액 `12만원` 등 비숫자 포함 | `입력 오류: 숫자만 입력해 주세요. 소수점 없이 만원 단위로 입력합니다.` | 같음. 붙여넣은 쉼표·공백은 오류가 아니라 정리 대상이다 |
| 카테고리 `기타` + 이름 빈 값 | `입력 오류: 직접 입력할 카테고리 이름을 입력해 주세요.` | 첫 오류 필드인 직접 입력 필드로 focus 이동 |
| 연회비 한도 음수 | `입력 오류: 0원 이상 금액을 입력해 주세요.` | 연회비 한도는 0원을 허용한다 |
| 미래지출 0건 → `카드 조건 확인하기` | `다음 단계로 이동할 수 없어요` / `미래지출을 한 건 이상 추가하면 카드 조건 단계로 이동할 수 있습니다.` | 금액 필드로 focus 이동, 2단계로 넘어가지 않음 |

- 오류는 색상만으로 구분하지 않는다. `입력 오류:` 접두사 텍스트, `role="alert"`, `aria-invalid`,
  `aria-describedby` 연결을 함께 사용한다(spec §8.6).
- 오류가 나도 입력값과 선택 상태(카테고리·지출 형태·시점)는 유지된다.

### 탭 전환의 상태 전이 (완료 기준 3)

탭은 미리 준비된 결과를 바꿔 보여줄 뿐 서버를 다시 호출하지 않는다(PRD US-A AC6).
선택 상태는 색상 외에 `✓` 표시·굵은 글씨·밑줄·`aria-selected`로 함께 전달한다.
접근성 이름에는 짧은 탭 라벨과 맥락 문구가 모두 들어간다(예: `더 적게, 예상 지출보다 적게 쓸 때`).

| 탭 | 결과 제목 | 결론 | 유지 대비 예상 차액 | 대표 예상 순혜택 | 총 예상 혜택 / 연회비 | 핵심 한도 문장 |
| --- | --- | --- | --- | --- | --- | --- |
| 더 적게 | 예상 지출보다 적게 쓸 때 결과 | 유지 · `현재 조합 유지` | 연 0원 | 연 48,000원 (예시 카드 A) | 연 48,000원 / 연 0원 | 생활 할인은 월 최대 1만 원까지 적용되며, 이 시나리오에서는 한도에 이르지 않았습니다. |
| 예상한 만큼 | 예상한 만큼 쓸 때 결과 | 변경 · `조합 변경` | 연 +93,000원 | 연 153,000원 (예시 카드 A + 예시 카드 B) | 연 162,000원 / 연 9,000원 | 생활 할인은 월 최대 1만 원까지 적용됩니다. |
| 더 많이 | 예상 지출보다 많이 쓸 때 결과 | 변경 · `조합 변경` | 연 +147,000원 | 연 231,000원 (예시 카드 A + 예시 카드 B) | 연 240,000원 / 연 9,000원 | 생활 할인은 월 최대 1만 원까지 적용되며, 계산상 할인 중 월 5,000원이 한도로 제외됐습니다. |

`더 적게` 탭의 결론 본문은 `현재 조합을 유지해도 예상 혜택 차이가 없습니다.`다. 우월성을 주장하지 않고
차이가 없다는 사실만 말한다(spec §9.2). 유지와 변경은 같은 배지·같은 카드 위계로 표시하며 변경을
성공 상태처럼 강조하지 않는다. 어떤 탭에도 `1위`·`최적` 같은 순위 표현이 없고 변경 후보는 한 건만
표시한다(spec §9.3).

## 화면 5 — `/result` 계산 근거 disclosure

- **접근 URL**: `http://localhost:3000/result` → `계산 근거 보기` 클릭 (탭별로 독립)
- **구현 파일**: `components/prototype/evidence-disclosure.tsx`
- **충족 완료 기준**: 4, 5, 6, 8

`계산 근거 보기`는 Base UI Accordion Trigger로 렌더되어 키보드로 열고 닫히며 제목과 연결된
`aria-expanded`를 제공한다. 접힌 상태에서도 할부 미반영 경계 문구는 바로 위에 노출된다(완료 기준 6).

접힌 상태의 패널은 SSR HTML에 포함되지 않으므로, 아래는 `예상한 만큼` 탭에서 펼쳤을 때 렌더되는
텍스트를 `components/prototype/evidence-disclosure.tsx`와 `fixtures/prototype/result.ts` 값으로
그대로 옮긴 것이다.

```
1 · 2. 영역별 예상 혜택 계산식과 한도 적용 전·후 금액

생활 할인

한도 적용      월 -2,500원
실제 적용      월 10,000원

실제 적용      월 3,000원

예식 결제 적립
계산상 할인    월 500원
한도 없음      적용된 차감 없음
실제 적용      월 500원

예상 순혜택     연 153,000원
예상 순혜택은 15만 3천 원이며, 총 예상 혜택·연회비·예상 순혜택은 모두
2026.09 ~ 2027.08 (12개월) 기준으로 환산했습니다.

4. 적용 조건
· 예시 카드 B의 생활 할인은 전월 실적 30만 원 이상일 때 적용됩니다. 이 시나리오의 예상 지출은 이 조건을 충족합니다.

· 할부 수수료
· 월별 실적 반영 차이
· 카드사별 무이자 할부 조건
· 포인트 소멸과 자동납부 승계 비용
· 카드 조건 단계의 예시 초기값
· 여러 변경 후보 사이의 순위와 대표 후보 선택
```

- 정형 근거 6종이 spec §10.2 순서대로 모두 있다. `계산상 할인 → 한도 적용 → 실제 적용` 3행으로
  한도 적용 전·후를 함께 보여준다.
- 한도는 `생활 할인 월 최대 1만 원`처럼 적용 영역과 기간을 함께 쓴다. 카드 전체 한도로 읽히는
  포괄 라벨을 쓰지 않고, 한도가 없는 영역은 `이 영역에는 적용 한도가 없습니다.`로 구분한다.

  순혜택이 현재 조합과 같습니다.`가 들어간다.
- AI 설명 영역과 비활성 placeholder는 만들지 않았다(spec §10.3).

## 뷰포트 증거 (완료 기준 7)

폭 375px 기준이다. 모든 화면이 한 컬럼이고 가로 스크롤을 만드는 고정 폭 요소가 없다.

| 화면 | 최상위 컨테이너 클래스 | 가로 스크롤 위험 요소 | 처리 방식 |

| `/plan` 항목 카드 | `rounded-lg border` | `수정하기`·`삭제하기` 버튼과 `수정 중`·`예시 금액` 배지 | 버튼 줄은 `flex flex-wrap justify-end gap-2`, 배지 줄은 `flex shrink-0 flex-wrap justify-end gap-1`로 좁은 폭에서 아래로 접힌다 |

## 완주 경로 (완료 기준 2)

새로고침 없이 이어지는 클릭 순서다.

```
http://localhost:3000/plan 진입
→ [예시 금액 적용하기]  (또는 카테고리·지출 형태·금액·시점 입력 후 [미래지출 추가하기])
→ 목록에 미래지출 1건 이상 표시됨
→ (선택) [수정하기] → 금액·시점 변경 → [수정 내용 저장하기]   ← 같은 화면에서 제자리 갱신
→ [카드 조건 확인하기]            ← 주소 이동 없이 /plan 2단계로 전환
→ 최대 카드 수·연회비 한도·신규 발급 허용 여부 확인
→ [결과 확인하기]                 ← /result 이동
→ 기본 진입은 [예상한 만큼] 탭
→ [더 적게] / [더 많이] 탭 전환    ← 서버 재호출 없이 결론·금액·근거가 함께 바뀜
→ [계산 근거 보기] 펼침            ← 정형 근거 6종 확인
```

각 단계에서 새로고침이 필요하지 않다. 1단계 → 2단계 전환은 같은 URL 안의 상태 전환이고,
`/result`로의 이동만 라우트 이동이다. 브라우저 뒤로가기를 막지 않는다.

## 범위 준수 증거 (완료 기준 9)

- 이번 라운드에서 GitHub Issue 상태를 변경하지 않았다. `gh issue`·`gh project` 계열 명령을 한 번도
  실행하지 않았고 어떤 TASK도 `Done`으로 닫지 않았다. 계획 정본 19건의 상태는 그대로다.
- 이번 범위에서 구현하지 않은 것: `/`·`/onboarding` 라우트, 플랫폼 연동 상태 화면, 상태 7종 전체
  (`loading`·`partial`·`stale`·`error`·`unavailable` 화면), 조합 선택과 외부 이동, `review=1` 검토자 상태 패널,
  RANGE 입력, AI 설명. 앞당겨 만든 화면이 없다.
- 금지 구현이 없다: `app/api/**` Route Handler, Server Action, Prisma, Supabase, 인증·미들웨어, AI 호출,
  실제 카드 혜택 계산 코드가 저장소에 없다. 화면은 Fixture 값을 읽어 표시만 한다.
- 금지 표현이 없다: 자동 카드 변경·대행 해지·`무조건 가장 유리`·`혜택을 보장`·외부 처리 완료 암시 문구,
  검증되지 않은 사용자 수·절감액·추천 보장 문구, 실제 카드사·플랫폼 실명과 로고를 쓰지 않았다.
  카드는 `예시 카드 A`·`예시 카드 B` 비식별 라벨만 사용한다.
- 스코프 고지(spec §7.2)는 `/plan` 입력 전에 표시된다. 조합 선택·외부 이동 고지는 해당 화면을 만들지
  않았으므로 함께 미룬다.
